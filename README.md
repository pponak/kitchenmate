# KitchenMate

KitchenMate 是一个个人菜谱管理练习项目。当前主版本使用 SQLite 保存菜谱，通过 Streamlit 提供页面，并可用 pywebview 在独立 Windows 窗口中显示。已生成 PyInstaller 目录版成品并完成本机隔离验收；早期的 JSON 命令行版本保留作学习记录。

## 当前功能

### Streamlit 页面（`app.py`）

- 显示菜谱的数据库 ID 和名称，展开查看已保存的分类、食材与步骤；菜谱标题、分类及步骤编号加粗，“食材”和“步骤”使用小标题，食材明细保持普通文字；
- 按名称关键词搜索、按分类筛选，并可勾选“只看收藏”。分类默认“全部”，表示不限制分类；名称、分类和收藏条件同时生效，只显示满足当前全部条件的菜谱。关键词为空时不限制名称，取消收藏筛选时仍保留名称和分类条件；
- 每份菜谱的详情标题上方显示收藏按钮：未收藏为 ☆，已收藏为 ★。点击可收藏或取消收藏，结果保存到 SQLite 并立即更新列表，重新打开后仍保留；在“只看收藏”模式下取消收藏，目标会立即从当前列表消失；
- 添加菜谱：可点击“添加食材”增加输入行，也可删除任意食材行；其他行已填的内容会保留。步骤在多行输入框中每行填写一条，空白行会跳过；
- 添加时可选择一个分类：主菜、配菜、汤羹、主食、甜点、饮品、其他，默认“其他”；有效提交时分类与菜谱一起保存。添加分类与列表筛选是两个独立选择框，“全部”仅用于筛选；
- 提交菜谱时，名称、至少一种食材和至少一条步骤不能为空。全空的食材行会跳过；若一行填了数量或单位却没填食材名称，页面会提示补全。食材数量和单位可以留空；
- 按数据库 ID 删除菜谱，并处理空 ID、非数字 ID 和不存在的 ID；
- 按数据库 ID 修改菜谱名称，并处理空名称、空 ID、非数字 ID 和不存在的 ID。修改后会重新查询并显示菜谱列表；
- 在菜谱详情中点击“编辑菜谱”，预填已保存的分类、食材和步骤；可修改分类、食材名称/数量/单位，增加或删除食材输入行，以及编辑多行步骤。点击“保存”且校验通过后，一次更新分类、食材与步骤，退出编辑并显示最新内容；原 ID、名称、收藏状态和其他菜谱保持不变；
- 编辑时可点击“取消编辑”放弃草稿并退出，已保存数据不变，再次编辑时恢复上次保存的分类、食材和步骤；即使必填内容为空，也可以直接取消。

添加或删除食材输入行只改变当前页面的表单；点击“提交”且输入有效时才保存新菜谱。删除菜谱按钮会立即删除找到的菜谱，目前没有二次确认。操作前请核对数据库 ID。

编辑时增删食材行也只改变表单，点击“保存”才更新数据库。全空食材行会跳过；只填数量或单位却缺名称、没有有效食材、没有有效步骤时会显示错误并保留编辑输入。清空一整行后成功保存，可移除该食材；删除全部输入行后仍可增加新行。重复点击同一份菜谱的编辑按钮会保留当前草稿，编辑输入尚未保存时不属于永久数据。

分类修改也遵循上述保存校验；食材或步骤无效时，整份修改（包括分类）都不会保存。保存后仍按当前名称、分类及收藏条件显示，例如在“主菜”筛选下把一份菜谱改为“汤羹”，它会从当前列表消失；切换到“汤羹”后可以找到它。

列表先从 SQLite 查询全部或名称匹配的菜谱，再由页面保留指定分类及收藏状态，按数据库 ID 升序显示。筛选只改变显示结果，不修改已保存数据。没有结果时，若勾选“只看收藏”，优先提示“没有符合当前条件的收藏菜谱”；未勾选时，有关键词提示搜索无匹配，没有关键词则区分“该分类下没有菜谱”和“没有菜谱”。例如，选择“主菜”、搜索“鸡蛋”并勾选“只看收藏”，只显示名称含“鸡蛋”、分类为“主菜”且已经收藏的菜谱。

### SQLite 命令行（`sqlite_main.py`）

支持添加、查看、按名称搜索、按数据库 ID 删除，以及修改菜谱名称。命令行添加时可以输入多个食材和步骤。`db_storage.py` 为页面和命令行提供同一套 SQLite 数据操作。

命令行目前没有分类输入或收藏操作入口，新增菜谱使用默认分类“其他”和未收藏状态。

## 运行方式

### 使用打包后的桌面版

打开 `dist\KitchenMate` 文件夹，双击 `KitchenMate.exe`。移动或分享时必须复制整个 `KitchenMate` 文件夹，包括 `_internal`，不能只复制 exe。当前保留控制台窗口，便于查看启动错误；正常退出请关闭 KitchenMate 菜谱窗口。

成品自带 Python 运行时和应用依赖，使用者无需自行运行 pip。窗口依赖 Windows 的 Microsoft Edge WebView2 Runtime；本机已有该组件，尚未在缺少 Python 或 WebView2 的另一台电脑上验收。仓库目前保存源码及构建配置，没有发布可下载的成品附件；`dist/` 不通过 Git 同步。

普通启动时，入口先检查本机 `8502` 端口，启动自己的页面服务，有限次检查就绪后才打开窗口；关闭窗口后停止并等待服务进程退出。若提示端口已占用，请先检查是否已有 KitchenMate 或其他服务在运行，不要直接结束不明进程。

### 从源码运行

本机已使用 Windows、Python 3.14.3、Streamlit 1.64.0、pywebview 6.2.1 运行。进入 `kitchenmate` 项目目录，在 PowerShell 或 cmd 中执行：

```cmd
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe window_practice.py
```

每台电脑建立自己的 `.venv`，不经 Git 同步。已有环境且依赖齐全时，直接运行最后一行；新增或更新依赖后重新执行安装命令。若环境中没有 pip，可先运行 `.\.venv\Scripts\python.exe -m ensurepip --upgrade`。当前数据目录依赖 Windows 的 `LOCALAPPDATA` 环境变量。

只使用浏览器页面时，可以单独启动：

```cmd
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8502 --server.headless=true --global.developmentMode=false
```

随后打开 `http://127.0.0.1:8502`，在该终端按 `Ctrl+C` 停止服务。浏览器方式和桌面方式不要同时占用同一个端口。`window_practice.py --server` 是启动器内部使用的服务分支，只启动服务，不打开窗口。

以下使用 `.\.venv\Scripts\python.exe` 的命令直接指定项目虚拟环境中的 Python，无需先激活虚拟环境；执行时需位于项目目录。

### 数据目录与旧数据

页面、桌面版和 SQLite 命令行共用的数据文件现在位于：

```text
%LOCALAPPDATA%\KitchenMate\kitchenmate.db
```

例如当前用户通常对应 `C:\Users\用户名\AppData\Local\KitchenMate\kitchenmate.db`。首次连接时自动创建目录和数据库；程序文件与用户菜谱分开保存，移动或替换成品文件夹不需要移动数据库。关闭应用后可以单独备份该文件，数据库不会随代码在电脑之间同步。

项目目录中原有的 `kitchenmate.db` 保留，不会自动迁移，也不会被当前入口读取。需要沿用旧菜谱时，先关闭所有使用该数据库的程序，分别备份旧库与用户目录中的库，再核对表结构与数据并决定迁移；不要直接覆盖已有用户库。当前尚无自动迁移工具。

当前 `recipes` 表需要 `id`、`name`、`ingredients`、`steps`、`category`、`favorite` 六列。新数据库会按此结构创建；已有表不会被 `CREATE TABLE IF NOT EXISTS` 自动升级。换电脑或更新旧版本时，请先备份并检查本机表结构；缺列的旧表需要保留数据地新增 `category TEXT DEFAULT '其他'` 或 `favorite INTEGER DEFAULT 0` 后再运行，只增加实际缺少的列。项目尚未提供自动迁移，拉取 Git 代码也不会更新本机数据库，不要为升级直接删除旧数据。

运行 SQLite 命令行版本：

```cmd
.\.venv\Scripts\python.exe sqlite_main.py
```

## 运行测试

在项目虚拟环境中安装 pytest 并运行页面与数据层测试：

```cmd
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q test_app.py test_db_storage.py
```

`test_db_storage.py` 包含十二个测试函数、十六个执行用例（分类保存、收藏、食材/步骤更新及分类修改分别运行两种情况）：

- 添加后关闭并重新连接，确认完整菜谱持久保存；
- 删除指定菜谱后，其他菜谱及其收藏状态保持不变；修改指定菜谱名称后，分类、食材、步骤、收藏状态及其他菜谱保持不变；
- 按 ID 更新食材和步骤，分别覆盖增加与减少内容；关闭再连接后，按 ID、查询全部及名称搜索都读回完整新内容，原名称、分类、收藏状态及其他菜谱不变，单引号和中文内容正常保存；
- 按 ID 只修改分类，覆盖改为“主菜”和“其他”；关闭重连后，三个查询接口都读回新分类，原食材、步骤、名称、收藏状态及其他菜谱不变；
- 明确分类“汤羹”与缺少分类时默认“其他”，均能在重新连接后由按 ID、查询全部、按名称搜索三个接口完整读回；
- 空数据库返回空列表或 `None`；名称部分匹配、多个结果按 ID 升序、无匹配返回空列表；
- 名称和搜索词中的单引号正常处理，类似 SQL 的搜索文字作为普通参数；
- 查询、修改、收藏或删除不存在的 ID，不改变已有菜谱；重复建表不丢失已有数据；
- 新菜谱默认未收藏；收藏或取消收藏后关闭再连接，按 ID、查询全部、名称搜索三个接口都返回正确状态，其他菜谱及字段保持不变。

临时数据库准备集中到 `db_path` fixture，示例菜谱集中到 `make_recipe()`，完整返回值的预期集中到 `expected_recipe()`；分类保存/修改、收藏和内容更新测试使用参数化复用流程。连接由 `closing()` 管理，即使断言失败也会关闭。

`test_app.py` 使用 Streamlit `AppTest` 模拟页面输入与按钮操作，包含二十个测试函数、三十六个执行用例；前五个函数保护已有页面行为：

- 添加食材行后，原输入保留、新行出现，未提交时数据库仍为空；
- 删除指定食材行后，该行输入框消失，其他行输入保留，数据库仍为空；
- 提交包含两种食材的菜谱后，数据库只有一份菜谱，名称、食材名称/数量/单位和步骤均正确；
- 已有有效食材时，另一行只填数量却缺名称，页面提示“请补全食材名称！”，整份菜谱不写入数据库；
- 分类与名称筛选测试：在临时数据库准备三份菜谱，连续检查“主菜 + 鸡蛋”“全部 + 鸡蛋”“主菜 + 空关键词”“全部 + 空关键词”的结果数量、名称和顺序；检查鸡蛋炒番茄的分类文字为“主菜”；选择没有菜谱的“甜点”或搜索无匹配的“面包”时，确认没有菜谱折叠区域且提示准确；全部筛选操作前后，数据库中的完整菜谱列表保持一致。这些场景属于同一个测试函数。

收藏相关的五个函数展开为十三个页面用例：

- 收藏与取消：检查默认空星、点击后的实心星、普通重运行不会再次切换、重新创建页面实例后状态保留；每次重新连接数据库比较完整记录，确认只改变目标的收藏状态；
- 七种组合筛选：收藏单独生效、与分类或名称结合、三个条件同时生效，以及关闭收藏筛选后的名称/分类组合和全部列表；检查结果 ID、名称、顺序、星星及收藏标题，完整数据库内容保持不变；
- 三种收藏无匹配场景：关键词无匹配、分类无匹配及两者均无匹配；确认没有菜谱详情和星星按钮，优先显示收藏提示；
- 有菜谱但没有收藏时：勾选后提示准确，取消勾选后全部菜谱恢复，已保存数据不变；
- 在收藏、分类和名称组合筛选后取消收藏：按数据库 ID 更新目标，该菜谱立即移出列表，其他菜谱及字段不变；取消收藏筛选后，名称和分类条件保留，目标以空星重新出现。

收藏页面测试用 `favorite_page_recipes` fixture 准备独立数据，辅助函数集中检查完整数据库记录、列表与星星及提示文字。组合筛选和无匹配场景使用参数化，减少重复准备代码。

编辑相关的十个函数展开为十八个页面用例：

- 分别打开原分类为“汤羹”和“主菜”的菜谱，预填各自分类、食材和步骤；分类选项不包含“全部”，进入编辑不写库；
- 增行保留已改的分类、数量、其他食材和步骤；连续增行、重复点击同一编辑按钮保留草稿，添加菜谱表单的行状态不受影响；
- 删除中间行保留其他输入，再添加使用未用过的行 ID；保存后只保留剩余有效食材；
- 清理输入首尾空格和步骤空白行，忽略新增全空食材行；保存后退出编辑、刷新详情，保留名称/分类/收藏筛选，普通重运行和重新打开仍读到新内容；
- 五种无效输入：有数量缺名称、有单位缺名称、食材全部为空、步骤为空及多个错误同时出现；提示准确，保留编辑状态、分类选择和输入，整份修改不写库；
- 清空原食材的整行后保存，该食材被移除，重新编辑时剩余食材正确预填；
- 删除全部行后拒绝保存，仍可增加新行并恢复保存；
- 取消有效或无效草稿：放弃分类、食材、步骤和增删行变化，退出编辑且保留筛选条件，重新进入时恢复已保存内容；
- 三种分类修改：汤羹改主菜、主菜改汤羹、主菜改其他；保存退出、普通重运行及重新打开页面后仍保留，其他字段和菜谱不变；
- 同时修改分类、食材和步骤，目标立即移出原分类列表；名称和收藏筛选保留，切换到新分类后显示更新内容。

编辑测试用 `edit_page_recipes` fixture 准备两份独立菜谱，覆盖不同分类及收藏状态，主要编辑场景的目标不是第一份且已收藏；通过比较完整记录保护原 ID、名称、收藏状态、未修改字段及其他菜谱。

每个执行用例都通过 pytest 的 `tmp_path` 创建独立的 SQLite 数据库；页面测试及数据层 fixture 用 `monkeypatch` 临时替换 `db_storage.DB_FILE`，测试结束后恢复。测试不会修改真实用户数据库。2026-10-16 更改数据目录和启动器后，助手在隔离数据下重跑整套，结果为 `52 passed`（三十六个页面用例、十六个数据层用例）；项目原数据库校验值未变，真实用户目录没有创建测试数据库。2026-10-15 本人也曾在隔离预览中确认编辑、取消草稿和分类筛选的代表性操作。以上结果不代表所有边界场景或独立开发能力均已验收；干净开发环境安装、测试及启动验收仍待完成。

## 数据与项目文件

一条菜谱包含 `id`、`name`、`ingredients`、`steps`、`category` 和 `favorite`。食材是字典列表，步骤是字符串列表；存入 SQLite 时，食材和步骤编码为 JSON 文本，读取时再还原为 Python 列表。分类是普通文本，直接保存和读取，不进行 JSON 编解码；保存函数在字典缺少 `category` 时使用“其他”。`favorite` 是整数，`0` 表示未收藏、`1` 表示已收藏；添加时由数据库默认值设为 `0`，`update_recipe_favorite()` 按 ID 更新并提交，三个查询接口直接返回该整数。页面根据它显示 ★/☆，按钮使用包含数据库 ID 的唯一 `key`；点击后写入目标状态、关闭当前连接，再通过 `st.rerun()` 重新查询并显示。只修改查询得到的 Python 字典不会自动写回数据库。

编辑状态由 `editing_recipe_id` 标识目标菜谱，编辑食材的行 ID 和下一个可用 ID 单独保存在 `st.session_state`。进入新的编辑目标时按原食材数量初始化；增删行回调更新状态后页面重跑，稳定组件 key 保留剩余输入。保存时先整理食材与步骤，再进行页面校验；通过后调用 `update_recipe_content(connection, category, recipe_id, ingredients, steps)`，将食材/步骤转成 JSON 文本，并在同一条按 ID 的 `UPDATE` 中写入分类、食材和步骤，`commit()` 后退出编辑、关闭连接和重新查询。取消编辑只退出并重跑，不调用更新函数。删除行不减少下一行 ID；再次进入编辑时按已保存列表重新初始化行编号。

页面与数据层的共用逻辑保持在以下两个模块中，启动器另负责窗口和服务的生命周期：

- `app.py` 的 `CATEGORY_OPTIONS` 统一添加、筛选及编辑的分类选项；筛选额外拼接“全部”，添加默认值和编辑预填通过 `.index()` 查找；
- `app.py` 的 `prepare_recipe_content(ingredient_inputs, steps_text)` 返回有效食材、有效步骤和名称缺失标记，添加/编辑共用整理规则；提示、校验及写入仍由各自的页面分支处理；食材输入框已先执行 `.strip()`，步骤在整理函数中逐行清理；
- `db_storage.py` 的 `row_to_recipe(row)` 统一六列查询行到菜谱字典的映射，供三个查询接口调用；按 ID 未找到记录时仍先返回 `None`，不调用转换函数。

## 当前限制与下一步

- 页面已支持编辑保存分类、食材和步骤，以及取消草稿；名称仍通过独立的按 ID 改名入口修改；
- 页面删除没有二次确认；
- 已有数据库尚无自动结构迁移，也无项目旧库到用户目录的自动数据迁移；
- 桌面版当前保留控制台，依赖 WebView2；无 Python 的另一台 Windows 电脑验收、干净开发环境按 README 安装/测试/启动验收仍待完成；
- 启动器采用固定端口和启动前占用检查，尚未覆盖多个实例同时启动的竞争；失败信息当前输出到控制台；
- 已有十六个 SQLite 数据层用例和三十六个页面用例，覆盖分类/内容编辑和持久化、取消草稿、动态食材行、校验、收藏交互及组合筛选。添加表单分类选择/默认选项、页面按 ID 删除/改名、切换编辑目标及其余边界场景尚未全部纳入自动化测试。

当前已完成桌面入口、数据目录分离、目录版打包、本机隔离验收和相应使用说明。下一步优先在另一台 Windows 电脑验证成品及数据保留，再继续阶段复盘与自主功能训练；如果暂时没有可用电脑，则保留验收待办。干净开发环境验收与无 Python 成品验收分别记录，不重建当前可用 `.venv`，也不把助手完成打包等同于本人已能独立交付。
