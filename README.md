# KitchenMate

KitchenMate 是一个个人菜谱管理练习项目。当前主版本使用 SQLite 保存菜谱，并通过 Streamlit 提供网页界面；早期的 JSON 命令行版本保留作学习记录。

## 当前功能

### Streamlit 页面（`app.py`）

- 显示菜谱的数据库 ID 和名称，展开查看已保存的分类、食材与步骤；
- 按名称关键词搜索，并按分类筛选菜谱。分类默认“全部”，表示不限制分类；指定分类与名称关键词同时生效，只显示两个条件都满足的菜谱。关键词为空时显示所选分类的全部菜谱；
- 添加菜谱：可点击“添加食材”增加输入行，也可删除任意食材行；其他行已填的内容会保留。步骤在多行输入框中每行填写一条，空白行会跳过；
- 添加时可选择一个分类：主菜、配菜、汤羹、主食、甜点、饮品、其他，默认“其他”；有效提交时分类与菜谱一起保存。添加分类与列表筛选是两个独立选择框，“全部”仅用于筛选；
- 提交菜谱时，名称、至少一种食材和至少一条步骤不能为空。全空的食材行会跳过；若一行填了数量或单位却没填食材名称，页面会提示补全。食材数量和单位可以留空；
- 按数据库 ID 删除菜谱，并处理空 ID、非数字 ID 和不存在的 ID；
- 按数据库 ID 修改菜谱名称，并处理空名称、空 ID、非数字 ID 和不存在的 ID。修改后会重新查询并显示菜谱列表。

添加或删除食材输入行只改变当前页面的表单；点击“提交”且输入有效时才保存新菜谱。删除菜谱按钮会立即删除找到的菜谱，目前没有二次确认。操作前请核对数据库 ID。

列表先从 SQLite 查询全部或名称匹配的菜谱，再由页面保留指定分类，按数据库 ID 升序显示。筛选只改变显示结果。没有结果时，有关键词会提示搜索无匹配；没有关键词时会区分“该分类下没有菜谱”和“没有菜谱”。例如，选择“主菜”并搜索“鸡蛋”，会显示“鸡蛋炒番茄（主菜）”，排除“鸡蛋汤（汤羹）”和“红烧排骨（主菜）”。

### SQLite 命令行（`sqlite_main.py`）

支持添加、查看、按名称搜索、按数据库 ID 删除，以及修改菜谱名称。命令行添加时可以输入多个食材和步骤。`db_storage.py` 为页面和命令行提供同一套 SQLite 数据操作。

命令行目前没有分类输入，新增菜谱由保存函数使用默认分类“其他”。

## 运行方式

已在 Windows、Python 3.14.3、Streamlit 1.64.0 下运行。进入 `kitchenmate` 项目目录后，在 cmd 中执行：

```cmd
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install streamlit==1.64.0
.\.venv\Scripts\streamlit.exe run app.py
```

每台电脑只需创建一次自己的 `.venv`。已有可用的 `.venv` 时，直接运行最后一行；若环境中没有 pip，可先运行 `.\.venv\Scripts\python.exe -m ensurepip --upgrade`。启动后在终端给出的本地地址打开页面，按 `Ctrl+C` 停止。

当前 `recipes` 表需要 `id`、`name`、`ingredients`、`steps`、`category`、`favorite` 六列。新数据库会按此结构创建；已有表不会被 `CREATE TABLE IF NOT EXISTS` 自动升级。换电脑或更新旧版本时，请先备份并检查本机表结构；缺列的旧表需要保留数据地新增 `category TEXT DEFAULT '其他'` 或 `favorite INTEGER DEFAULT 0` 后再运行，只增加实际缺少的列。项目尚未提供自动迁移，拉取 Git 代码也不会更新本机数据库，不要为升级直接删除旧数据。

运行 SQLite 命令行版本：

```cmd
.\.venv\Scripts\python.exe sqlite_main.py
```

## 运行测试

在项目虚拟环境中安装 pytest 并运行页面与数据层测试：

```cmd
.\.venv\Scripts\python.exe -m pip install pytest==9.1.1
.\.venv\Scripts\python.exe -m pytest -q test_app.py test_db_storage.py
```

`test_db_storage.py` 包含十个测试函数、十二个执行用例（分类测试运行两种情况，收藏测试运行收藏与取消收藏两种情况）：

- 添加后关闭并重新连接，确认完整菜谱持久保存；
- 删除指定菜谱后，其他菜谱及其收藏状态保持不变；修改指定菜谱名称后，分类、食材、步骤、收藏状态及其他菜谱保持不变；
- 明确分类“汤羹”与缺少分类时默认“其他”，均能在重新连接后由按 ID、查询全部、按名称搜索三个接口完整读回；
- 空数据库返回空列表或 `None`；名称部分匹配、多个结果按 ID 升序、无匹配返回空列表；
- 名称和搜索词中的单引号正常处理，类似 SQL 的搜索文字作为普通参数；
- 查询、修改、收藏或删除不存在的 ID，不改变已有菜谱；重复建表不丢失已有数据；
- 新菜谱默认未收藏；收藏或取消收藏后关闭再连接，按 ID、查询全部、名称搜索三个接口都返回正确状态，其他菜谱及字段保持不变。

临时数据库准备集中到 `db_path` fixture，示例菜谱集中到 `make_recipe()`，完整返回值的预期集中到 `expected_recipe()`；分类和收藏测试使用参数化复用流程。连接由 `closing()` 管理，即使断言失败也会关闭。

`test_app.py` 使用 Streamlit `AppTest` 模拟页面输入与按钮操作，包含五条回归测试：

- 添加食材行后，原输入保留、新行出现，未提交时数据库仍为空；
- 删除指定食材行后，该行输入框消失，其他行输入保留，数据库仍为空；
- 提交包含两种食材的菜谱后，数据库只有一份菜谱，名称、食材名称/数量/单位和步骤均正确；
- 已有有效食材时，另一行只填数量却缺名称，页面提示“请补全食材名称！”，整份菜谱不写入数据库；
- 分类与名称筛选测试：在临时数据库准备三份菜谱，连续检查“主菜 + 鸡蛋”“全部 + 鸡蛋”“主菜 + 空关键词”“全部 + 空关键词”的结果数量、名称和顺序；检查鸡蛋炒番茄的分类文字为“主菜”；选择没有菜谱的“甜点”或搜索无匹配的“面包”时，确认没有菜谱折叠区域且提示准确；全部筛选操作前后，数据库中的完整菜谱列表保持一致。这些场景属于同一个测试函数。

每个执行用例都通过 pytest 的 `tmp_path` 创建独立的 SQLite 数据库；页面测试及数据层 fixture 用 `monkeypatch` 临时替换 `db_storage.DB_FILE`，测试结束后恢复。测试不会修改本机的 `kitchenmate.db`。2026-10-10 最新验证结果为 `17 passed`（五条页面测试、十二个数据层用例），仅代表现有断言覆盖的场景通过。

分类保存、默认值和三个查询接口读回现已纳入永久数据层测试。添加表单的默认分类选项及选择分类后提交，曾做一次性 AppTest 验证，尚未专门加入永久页面断言。

## 数据与项目文件

一条菜谱包含 `id`、`name`、`ingredients`、`steps`、`category` 和 `favorite`。食材是字典列表，步骤是字符串列表；存入 SQLite 时，食材和步骤编码为 JSON 文本，读取时再还原为 Python 列表。分类是普通文本，直接保存和读取，不进行 JSON 编解码；保存函数在字典缺少 `category` 时使用“其他”。`favorite` 是整数，`0` 表示未收藏、`1` 表示已收藏；添加时由数据库默认值设为 `0`，`update_recipe_favorite()` 按 ID 更新并提交，三个查询接口直接返回该整数。收藏按钮及只看收藏的页面入口尚未接入。

```text
kitchenmate/
├── app.py          # 当前 Streamlit 页面
├── db_storage.py   # SQLite 连接、建表、查询、添加、修改和删除
├── sqlite_main.py  # SQLite 命令行入口
├── kitchenmate.db  # 本机数据，首次运行时创建，不经 Git 同步
├── db_practice.py  # 早期 SQLite CRUD 练习
├── test_db_storage.py  # 十二个临时数据库用例，覆盖 CRUD、分类、收藏、搜索及边界
├── test_app.py     # 五条 AppTest 页面测试，含分类/名称组合筛选与分类空结果
├── main.py         # 历史 JSON 命令行版本
├── storage.py      # 历史 JSON 读写
├── recipes.json    # 历史 JSON 示例数据
├── README.md
└── .gitignore
```

代码通过 Git/GitHub 同步。`kitchenmate.db` 被 `.gitignore` 排除，因此两台电脑的 SQLite 菜谱数据各自独立。`recipes.json` 虽写在 `.gitignore` 中，但已被 Git 跟踪，仍会随代码仓库同步；当前主版本不读取它。

- 页面添加支持多种食材和多条步骤；已保存菜谱目前只能在页面修改名称，不能编辑食材和步骤；
- 页面删除没有二次确认；
- 分类已支持选择、保存、三个查询接口读回、详情展示及与名称搜索组合筛选；收藏的建表、更新、查询读回和数据层验证已完成，页面星星按钮及只看收藏的入口尚未实现；
